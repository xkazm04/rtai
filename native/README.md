# native

The native bubble sim (STANDARDS NAT-01..12), loaded by `project/native/gtai_sim.gdextension`.

- `sim_core/src/`: plain C++17, no `godot::` types (NAT-03). `city_core.h` declares `CityCore`
  (struct-of-arrays slots); its member functions are split over TUs of 200 lines or fewer
  (world, spawn, step, hash, people, contact, car_route, car_drive, car_hit, projectiles,
  render, snapshot). `sim_constants.h` is GENERATED by `tools/gen_constants/gen.mjs` (NAT-08).
  The maths matches the GDScript reference in `project/features/city/sim/` operation for
  operation (NAT-07), and the parity gate (`project/tests/parity/run_parity.gd`) proves it.
- `sim_core/tests/`: a standalone test executable (no godot): determinism and behaviour checks.
- `binding/`: the thin godot-cpp `CitySim` class (argument checks, packed arrays to pointers,
  RenderingServer upload) and the `gtai_sim_init` entry point.
- `godot-cpp/`: git submodule pinned in `GODOT_CPP_VERSION` and `versions.toml`, built with
  `api_version=4.7` (NAT-04). Clone with `git submodule update --init`.

Build (x64, MSVC on Windows; SCons only, NAT-05), from this folder:

```
scons platform=windows arch=x86_64 target=template_debug
scons platform=windows arch=x86_64 target=template_release
scons platform=windows arch=x86_64 tests && build/tests/sim_core_tests.exe
```

Libraries land in `project/native/bin/` (git-ignored); objects in `native/build/`. The core TUs
compile with `/fp:strict` (MSVC) or `-ffp-contract=off` (gcc/clang). After the first build run
`godot --headless --path project --import` once so Godot registers the extension.
